# 1.0 — Zone de trajet (Isochrone)

## Vision produit

Permettre à l'utilisateur de visualiser sur une carte la zone géographique depuis laquelle il peut atteindre **deux adresses** (domicile, travail…) en un temps de trajet maximum donné.

L'intersection des deux zones isochrones représente les endroits où il est possible de vivre pour rejoindre les deux destinations dans le temps imparti.

---

## Fonctionnement attendu

1. L'utilisateur saisit deux adresses (rue complète ou ville ou code postal)
2. Il définit un temps maximum de trajet (en minutes)
3. Il choisit une heure de départ indicative
4. L'application calcule et affiche sur la carte :
   - Zone isochrone de l'adresse 1 (bleu, semi-transparent)
   - Zone isochrone de l'adresse 2 (rouge, semi-transparent)
   - **Intersection** des deux zones (vert) — la zone valide

> **Trafic** : pas de données temps réel (payant). Le trafic est estimé via un coefficient statistique
> par heure de départ (voir section dédiée). Un avertissement sera affiché à l'utilisateur.

---

## URL

La fonctionnalité est accessible à l'URL `/commute-zone`, servie par `src/commute_zone.php`.

Page dédiée `src/commute_zone.php`, partageant le même `<head>` (CSS, Leaflet, Turf.js) que `index.php`.

```

│                                             │
│  ⚠ Trafic estimé (statistiques moyennes)    │

│                                             │

└─────────────────────────────────────────────┘
```

L'interface affiche en temps réel le temps ajusté qui sera soumis à ORS (après application du coefficient trafic), pour que l'utilisateur comprenne l'impact de l'heure choisie.

La carte Leaflet existante est réutilisée pour afficher les polygones.

## Architecture technique

### Outils open source

| Outil | Rôle | Contraintes |
|---|---|---|
| [OpenRouteService](https://openrouteservice.org/) (API publique) | Génération des isochrones | Clé API gratuite, 500 req/jour, 40 req/min |
| [Nominatim](https://nominatim.org/) (OSM) | Géocodage des adresses texte → coordonnées | Gratuit, max 1 req/s, aucune inscription |
| [Turf.js](https://turfjs.org/) | Calcul de l'intersection des deux polygones (client) | ~170 KB, aucun serveur |
| Leaflet.js | Affichage des polygones sur la carte | Déjà présent |

### Nouveau fichier backend : `src/isochrone_api.php`

Endpoint POST (`Content-Type: application/json`) :

```
POST /isochrone_api.php
{ "address1": "...", "address2": "...", "max_minutes": 45, "departure_time": "07:00" }

→ { "poly1": <GeoJSON>, "poly2": <GeoJSON> }
```

Pipeline :
1. Géocodage de chaque adresse via Nominatim (cURL)
2. Application du coefficient trafic : `effective_minutes = max_minutes / TRAFFIC_FACTOR[hour]`
3. Appel ORS `/v2/isochrones/driving-car` avec `effective_minutes` pour chaque coordonnée
4. Mise en cache SQLite (TTL 24 h, même `SqliteLogger` existant)
5. Retour des deux polygones GeoJSON

### Nouveaux fichiers frontend

| Fichier | Rôle |
|---|---|
| `src/commute_zone.php` | Page HTML de la fonctionnalité (formulaire + carte) |
| `src/assets/commute_zone.js` | Logique JS dédiée (3 fonctions ci-dessous) |

Fonctions JS dans `commute_zone.js` :

| Fonction | Rôle |
|---|---|
| `getIsochroneState()` | Lit le formulaire |
| `applyTrafficFactor(minutes, hour)` | Retourne `minutes / TRAFFIC_FACTORS[hour]` |
| `fetchIsochrones(state)` | POST vers `isochrone_api.php`, retourne les deux polygones |
| `renderIsochrones(poly1, poly2)` | Intersection via Turf.js, affichage via `L.geoJSON` |

Constante dans `commute_zone.js` :

```js
// Coefficients de ralentissement moyen par heure (source : Vias Institute / TomTom Traffic Index BE)
// 1.0 = flux libre, 1.4 = 40% de temps en plus
const TRAFFIC_FACTORS = {
   0: 1.00,  1: 1.00,  2: 1.00,  3: 1.00,  4: 1.00,
   5: 1.05,  6: 1.15,  7: 1.35,  8: 1.40,  9: 1.25,
  10: 1.10, 11: 1.05, 12: 1.10, 13: 1.05, 14: 1.05,
  15: 1.15, 16: 1.30, 17: 1.40, 18: 1.35, 19: 1.20,
  20: 1.10, 21: 1.05, 22: 1.00, 23: 1.00,
};
```

### Partage du `<head>` entre pages

**Approche : extraction d'un partial PHP `src/lib/_head.php`**

`index.php` et `commute_zone.php` partagent les éléments statiques du `<head>` (meta, favicon, Leaflet CSS, app.css, GoatCounter). Les constantes JS, elles, sont spécifiques à chaque page et restent dans le fichier appelant.

**`src/lib/_head.php`** (nouveau fichier) :
```php
<!DOCTYPE html>
<html lang="<?= h($lang) ?>">
<head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title><?= h($title) ?></title>
    <link rel="icon" type="image/svg+xml" href="assets/favicon.svg">
    <link rel="stylesheet" href="https://unpkg.com/leaflet@1.9.4/dist/leaflet.css">
    <link rel="stylesheet" href="assets/app.css">
```
> Le fichier s'arrête **sans fermer `</head>`** — chaque page ajoute ses propres `<script>` puis ferme elle-même.
> Les variables `$lang`, `$title`, `$infra` doivent être définies avant l'`include`.

**Dans `index.php`** (modification) :
```php
$title = $t['title'] ?? 'Recherche Immobilière';
require __DIR__ . '/lib/_head.php';

    <script>const DEFAULT_CONFIG = ...;  /* constantes existantes */</script>

    <script data-goatcounter="..." ...></script>
    <?php endif; ?>
</head>
```

**Dans `commute_zone.php`** (nouveau) :
```php
$title = $t['cz_page_title'] ?? 'Zone de trajet';
require __DIR__ . '/lib/_head.php';
?>
    <script src="https://unpkg.com/@turf/turf@6/turf.min.js"></script>

```
> La clé ORS reste **exclusivement côté serveur** dans `isochrone_api.php` — ne jamais l'injecter dans le HTML.

### Détails API Nominatim — Géocodage

**Endpoint :**
```
GET https://nominatim.openstreetmap.org/search?q=<adresse>&format=json&limit=1&countrycodes=be
```

**Headers :**
```
User-Agent: maizoek/1.0 (bout_largo_0g@icloud.com)
```
> Le header `User-Agent` est **obligatoire** — Nominatim bloque les requêtes sans lui (conditions d'utilisation).

**Exemple de requête PHP (cURL) :**
```php
$url = 'https://nominatim.openstreetmap.org/search?'
     . http_build_query(['q' => $address, 'format' => 'json', 'limit' => 1, 'countrycodes' => 'be']);
curl_setopt($ch, CURLOPT_HTTPHEADER, ['User-Agent: maizoek/1.0 (bout_largo_0g@icloud.com)']);
```

**Réponse (tableau JSON) :**
```json
[
  {
    "lat": "50.6292",
    "lon": "5.5797",
    "display_name": "Liège, Province de Liège, Wallonie, Belgique"
  }
]
```
> `lat` et `lon` sont des **strings** — caster en float avant usage.
> Tableau vide `[]` = adresse introuvable → renvoyer une erreur claire à l'utilisateur.
> Pour ORS, l'ordre est inversé : `[lon, lat]`.

**Limite :** 1 requête/seconde — respectée naturellement car les deux géocodages sont séquentiels.

### Détails API ORS — Isochrones

**Endpoint :**
```
POST https://api.openrouteservice.org/v2/isochrones/driving-car
```

**Headers :**
```
Authorization: <ors_api_key>
Content-Type: application/json
```
> Pas de préfixe `Bearer` — la clé brute suffit.

**Body (exemple pour 32 minutes = 1920 secondes) :**
```json
{
  "locations": [[5.5797, 50.6292]],
  "range": [1920],
  "range_type": "time"
}
```
> `locations` : tableau de `[longitude, latitude]` — attention, c'est **lng/lat**, pas lat/lng.
> `range` : en **secondes** (multiplier les minutes par 60).
> Un seul appel = une seule adresse. Deux adresses = deux appels séparés.

**Réponse (GeoJSON FeatureCollection) :**
```json
{
  "type": "FeatureCollection",
  "features": [
    {
      "type": "Feature",
      "geometry": {
        "type": "Polygon",
        "coordinates": [[[5.45, 50.58], [5.46, 50.59], ...]]
      },
      "properties": {
        "group_index": 0,
        "value": 1920.0,
        "center": [5.5797, 50.6292]
      }
    }
  ]
}
```
> On extrait `features[0].geometry` (GeoJSON Polygon) pour Turf.js et Leaflet.

**Réponse en cas d'erreur :**
```json
{
  "error": {
    "code": 2003,
    "message": "The given request is not supported."
  },
  "info": { ... }
}
```
> Détecter via l'absence de `features` ou la présence de `error` dans la réponse.

**Limites du plan gratuit :**
- 500 requêtes / jour
- 40 requêtes / minute
- Chaque calcul = 2 appels (une par adresse) → 250 calculs / jour effectifs

### Stratégie de cache SQLite

Même base `cache.sqlite`, nouvelle table créée à la volée (pattern identique à `search.php`).

**Schéma :**
```sql
CREATE TABLE IF NOT EXISTS isochrone_cache (
    cache_key  TEXT    NOT NULL PRIMARY KEY,
    geojson    TEXT    NOT NULL,
    cached_at  INTEGER NOT NULL
)
```

**Clé de cache :** calculée après géocodage sur les coordonnées arrondies + durée effective.
```php
$cache_key = number_format($lat, 4, '.', '') . ',' . number_format($lng, 4, '.', '') . ':' . $effective_seconds;
```
> Même précision (4 décimales) que `location_cache` dans `search.php`.
> Clé basée sur les coordonnées (pas l'adresse texte) → "Liège" et "4000 Liège" donnent la même entrée cache.

**TTL :** 24 h (`24 * 3600`) — les isochrones ne changent pas souvent, contrairement aux codes postaux (30 j).

**Fonctions à créer dans `isochrone_api.php` :**
```php
function open_isochrone_cache(): PDO { ... }          // identique à open_cache() de search.php
function iso_cache_get(PDO $db, string $key): ?string  // null = miss
function iso_cache_set(PDO $db, string $key, string $geojson): void
```

## Ce qui est hors scope

- Trafic temps réel (nécessite une API payante)
- Affinement des coefficients trafic par ville ou par axe routier
- Profils autres que voiture (vélo, transports en commun)
- Sauvegarde des zones en cookie
- Plus de deux adresses
